# Equator standards sources

The consumer configuration profile `equator-1` resolves to the exact standards and source-data selection in `sources.lock.json`. Consumers select the Equator profile; they do not maintain Unicode, CLDR, IANA, or XLIFF versions themselves. Section 1 of `specs/01-standards-profile.spec.md` declares that profile, and section 4 of `specs/01-standards-profile.spec.md` is why every source behind it is recorded here rather than known only to whoever installed it.

Every digest is an explicit `{ algorithm, encoding, value }` object. Hex values are not Subresource Integrity strings.

`data/sitemaps-0.9-schemas/` mixes three publishers and one file of Equator's own, and the lock records each separately. `sitemap.xsd` and `siteindex.xsd` are sitemaps.org's; `xhtml1-strict.xsd` is W3C's, vendored because the hreflang extension is Google's and neither publisher's schema imports the other's; `sitemap-hreflang.xsd` is ours and is marked as ours. That last file is an import and no more. Both sitemap schemas end every content model with `<xsd:any namespace="##other" processContents="strict"/>`, and `strict` means a validator must find a global declaration for `xhtml:link` or reject the document; making the XHTML schema merely findable does not answer it, because the namespace has to be imported into the compiled set. A sitemap index is validated against `siteindex.xsd` directly instead, since it carries no foreign element and the two sitemap schemas share a namespace, so a second import of that namespace is skipped. `xhtml1-strict.xsd` imports the W3C `xml.xsd` vendored beside the XLIFF schemas; one copy serves both sets, and its digest is already recorded there.

One file in `data/xliff-2.2-cs01-schemas/` is not OASIS's: `xml.xsd` is W3C's, and it is vendored alongside the twelve because the core schema imports it and the validator resolves nothing over the network. The lock records the two publishers separately even though the files share a directory. `itsm.xsd` carries an import of `xliff_core_2.0.xsd`, which OASIS does not ship in that directory; nothing Equator validates reaches it, and the lock says so rather than leaving a reader to discover a dangling reference.

`DerivedBidiClass.txt` is the one file here whose defaults live outside its data lines. Unassigned
code points in blocks reserved for right-to-left scripts take `R` or `AL`, and the file carries that
on `@missing:` lines rather than listing the code points. A reader that parses only the data lines
gets a class that is correct for every character that exists today and wrong for the next one added
to the Arabic block. The generator applies the `@missing` defaults first and lets every explicit
line override them.

Each vendored source's license asks for a notice to travel with copies, except the IANA registry's CC0 dedication and Equator's own file. The notice sits in `data/` beside what it covers: the Unicode license beside `DerivedBidiClass-17.0.0.txt`, the tz database's `LICENSE` beside the `tzdata-2026e` directory, the edition's own copyright and license annex beside the ECMA-402 extract, the CLDR and MessageFormat releases' own `LICENSE` files inside their directories, the OASIS notices for the XLIFF schemas, the W3C license and short notice for `xml.xsd` and `xhtml1-strict.xsd`, and the attribution and license for the sitemaps.org schemas. The lock records each notice by digest, or records why a source needs none, and `verify:standards-sources` fails on a vendored source with neither and on any file in `data/` that no source records.

## Update policy

A source update is never selected by a floating URL or an install-time network lookup. The maintainer must:

1. select an official immutable release or stage;
2. acquire it from the authoritative publisher;
3. verify byte length and digest against the publisher's checksum when available;
4. preserve a project-owned copy when the authoritative source is rolling;
5. review semantic and licensing changes;
6. regenerate affected fixtures and run the complete Equator verification suite;
7. change the Equator profile identifier when compatibility requires consumers to opt into changed behavior.

The project-owned IANA registry snapshot is an authoritative build input only after its file date, byte length, and digest match `sources.lock.json`.
